# Клиентская навигация с обычными URL

Для «Календаря встреч» выбираем React Router с BrowserRouter: главная страница `/` отделена от гостевого пути `/booking` и раздела владельца `/admin`. Вместо URL с `#` и отдельных серверных страниц используем клиентскую маршрутизацию: она сохраняет прямые ссылки и историю браузера и позволяет развивать многошаговую запись в существующем React-приложении. Go остаётся API-сервером; статические страницы этого этапа не обращаются к `/health` и доступны без работающего API.

При публикации хостинг должен возвращать HTML приложения для клиентских маршрутов, не подменяя ответы API и статических ресурсов. Сейчас прямое открытие и обновление маршрутов проверяем через Vite dev и Preview; настройка production-хостинга относится к этапу публикации. Неизвестный клиентский маршрут показывает страницу «Страница не найдена», а не перенаправляет на главную.
