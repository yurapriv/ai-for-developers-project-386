# Каркас приложения: от выбора инструментов к воспроизводимому запуску

Label: wayfinder:map
Status: resolved

## Destination

Согласован проверенный по официальной документации план каркаса: бекенд и фронтенд запускаются локально, TypeSpec → OpenAPI → SDK работает на техническом endpoint, одна команда запускает проверки локально и в GitHub Actions.
План достаточен для последующей реализации без функциональности бронирования.

## Notes

- Учебный проект «Запись на звонок», второй шаг — каркас приложения. Пользователь подтвердил границы и порядок работы в текущем обсуждении.
- Этот проход wayfinder только исследует и планирует. Установка инструментов и реализация каркаса — следующий проход после согласования решений.
- Приоритет — нативная Windows / PowerShell; WSL допустим, если потребуется. Linux используется в GitHub Actions.
- Выбор стека зафиксирован в закрытом билете в Decisions so far; исходное исследование Node.js-бекендов остаётся сравнением альтернатив, а не выбранной реализацией.
- Уже в каркасе нужен технический endpoint проверки работоспособности, сгенерированный SDK и обращение к бекенду из фронтенда через этот SDK.
- Проверки включают линтер, проверку типов при наличии и дымовой тест настоящего запуска приложения с успешным HTTP-ответом. Та же общая команда вызывается в отдельном workflow на каждый push.
- Рассмотреть mise, hk и daemons с зафиксированной версией pitchfork; проверить поддержку Windows, а не предполагать её. Подбор проверок сверить с dev-guardrails.
- После реализации выполнить инициализацию агента и сократить существующий AGENTS.md, сохранив ограничения Хекслета и указатели конфигурации навыков. Добавить рабочие команды и правило Conventional Commits.
- `.github/workflows/hexlet-check.yml` сохраняется без изменений. Релизы release-please на этом шаге не подключаются.
- Доменный сценарий и исходные требования находятся в README.md. Для исследования использовать навык `research`; для решений — `grilling` и `domain-modeling`.
- Карта и билеты локальные; порядок работы и блокировки — по `docs/agents/issue-tracker.md`. Исследования ведутся в отдельных временных ветках `research/scaffold-*`; они не сливаются в main. Коммиты и публикация результатов требуют отдельного согласования конкретного плана.

- Публикация сервиса, release-please и автоматические релизы.
- Авторизация, личные кабинеты, интеграции календарей и уведомления.
