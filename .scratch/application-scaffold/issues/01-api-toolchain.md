# Проверить цепочку TypeSpec → OpenAPI → TypeScript SDK и варианты стека

Type: research
Status: resolved

## Question

Какая актуальная, документированная связка TypeSpec → OpenAPI → клиентский SDK подходит TypeScript-фронтенду, и какие варианты бекенда и фронтенда совместимы с ней?

Проверить по первичным источникам:

- Актуальные требования TypeSpec и OpenAPI emitter к Node.js и поддерживаемые версии OpenAPI.
- Наличие и состояние генератора TypeScript SDK, runtime транспорта, требования к входному OpenAPI и команды генерации.
- Минимум два реалистичных варианта бекенда, включая Fastify и Hono, и возможность генерации серверных типов, валидации и маршрутов. Отделить официальный стабильный путь от экспериментальных и сторонних генераторов.
- Официальный getting started для React + Vite; варианты Mantine и shadcn/ui, требования к версиям и объём дополнительной настройки.
- Совместимый набор опубликованных версий и команды будущей проверки на техническом endpoint без бизнес-API. Сейчас ничего не устанавливать и не генерировать.

Нужны рекомендация, альтернативы, ограничения и ссылки. Поддержка SDK должна быть установлена до окончательного выбора стека.

## Answer

По документации, npm metadata и исходникам осуществима цепочка TypeSpec 1.17.0 → OpenAPI 3.0.0 YAML → Hey API 0.99.0 → TypeScript Fetch SDK. У emitter доступны также OpenAPI 3.1.0 и 3.2.0, но 3.0.0 предложен как консервативный общий формат. Fetch transport встроен в Hey API; отдельный старый npm client-fetch не нужен. Полная генерация и установка пока не выполнялись.

Проверены Fastify и Hono. Hey API Fastify plugin — Beta и генерирует типы обработчиков, но не маршруты и runtime validation. Fastify routes/schema из OpenAPI реализует сторонний fastify-openapi-glue. Для Hono сторонний Orval имеет server templates; Hey API Hono пока Planned. Ручная серверная реализация по emitted контракту с проверкой реального ответа контрактным тестом остаётся допустимым вариантом без обещаний полной автоматической генерации.

Документированный frontend-путь — React + Vite. Mantine предлагает готовые npm-компоненты; shadcn/ui добавляет исходники компонентов и Tailwind-настройку. Для технической health-страницы можно отложить обе библиотеки.

Общий кандидат runtime — Node 24.22.2 LTS с bundled npm 11.19.1. Исследование API предлагает TS 5.9.3 ради совместимости с запасным openapi-typescript; это не обязательное ограничение основной Hey API-цепочки. Исследование проверок рассматривает TS 7 и отдельно отмечает ограничения typescript-eslint. Нельзя механически объединять предложенные таблицы версий: при выборе стека нужно согласовать один компилятор и фактически выбранные генераторы/линтеры, без зависимости от неиспользуемого fallback.

Подробности, сравнение вариантов, точные опубликованные версии, пример health-контракта и первоисточники: [TypeSpec → OpenAPI → TypeScript SDK и варианты стека](file:///C:/Users/prive/AppData/Local/Temp/opencode/scaffold-api-research/docs/research/scaffold-api.md).

Артефакт находится в worktree ветки `research/scaffold-api`, файл `docs/research/scaffold-api.md`. Он пока не закоммичен и не опубликован; публикация требует отдельного согласования. Совместимость всего разрешённого дерева, native binaries, generated imports, CORS и воспроизводимость должны быть подтверждены установкой, генерацией, сборкой и тестами после выбора стека.
