# Проверить Go-бекенд и генерацию сервера из OpenAPI

Type: research
Status: resolved

## Question

Какой минимальный документированный Go-бекенд и генератор серверных типов/маршрутов подходят каркасу с TypeSpec → OpenAPI → TypeScript SDK, нативной Windows и Ubuntu CI?

Пользователь хочет попробовать Go для бекенда. Он iOS-разработчик, поэтому приоритет — понятная небольшая структура без лишнего фреймворка. Предпочтение простой реализации не отменяет требования использовать подходящую серверную генерацию, если она реально доступна.

Проверить первичные источники:

- Актуальный Go getting started / HTTP server, опубликованную stable-версию, Windows-установку и управление Go через mise; не выполнять установку.
- Стандартный net/http с современным ServeMux против лёгкого chi; Gin рассмотреть только при реальной необходимости. Совместимость с будущим контейнером, без Docker на этом этапе.
- oapi-codegen и альтернативы: поддерживаемый OpenAPI, генерацию моделей, маршрутов/обёрток, strict server interfaces, runtime validation, совместимость с TypeSpec OpenAPI 3.0.0 и Windows. Отделить типизацию от runtime request/response validation.
- Воспроизводимые pins генератора/Go tools, go.mod/go.sum, инструменты генерации без глобального go install latest.
- Минимальные Go lint/format/typecheck/test команды по текущему dev-quality-gates; учесть существующий TypeScript-фронтенд и единый check. Нужен ли Go test runner отдельно от TS Vitest и как не создавать два обязательных одинаковых smoke-теста.

Результат — один отчёт со ссылками, рекомендованным минимальным набором и ограничениями. Go-код, конфиги приложения, установки и тесты на этом проходе не создаются.

## Answer

По опубликованной документации и исходникам подходит Go 1.27.3 + стандартные net/http / ServeMux + oapi-codegen v2.8.2 с models, std-http-server, strict-server и embedded-spec. Генерируются модели, интерфейс операций, адаптеры и регистрация маршрутов; вручную остаются реализация интерфейса и запуск сервера. Gin / chi для такого каркаса не требуются.

oapi-codegen v2.8.2 документирует поддержку OpenAPI 3.1, но для согласования предложен консервативный общий OpenAPI 3.0.0 из TypeSpec. Strict-типы не заменяют runtime validation: nethttp-middleware v1.3.1 проверяет запросы, kin-openapi v0.152.0 позволяет проверять ответы в контрактном тесте. Сгенерированный загрузчик спецификации GetSpec() не создаёт Swagger UI; старое GetSwagger() deprecated.

Предложен один настоящий process+HTTP smoke в go test с запуском готового бинарника и проверкой ответа по тому же emitted контракту. Не дублировать этот запуск в Vitest. Для Go доступны стандартные format/vet/build/test и golangci-lint 2.15.0 с заявленной поддержкой Go 1.27; расширенные gates должны быть отдельно выбраны в билете о проверках.

mise может закрепить официальный Go compiler; GOTOOLCHAIN=local предотвращает скрытое переключение компилятора. Генератор предложено запускать через go run с точной версией, изолируя его module graph от приложения, а не через глобальный latest. go.sum хранит checksums, а не является lockfile выбора версий.
