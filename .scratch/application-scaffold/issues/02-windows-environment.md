# Проверить воспроизводимое окружение Windows и Linux CI

Type: research
Status: resolved

## Question

Как воспроизводимо управлять инструментами, задачами, git-хуками и фоновыми процессами в нативной Windows / PowerShell и Linux CI, и где действительно потребуется WSL или замена инструмента?

По официальной документации и исходникам проверить mise, hk и pitchfork / mise daemons: поддержку платформ, ограничения, experimental-настройки, фиксацию версий, способы установки и синтаксис задач.

Исходное окружение: Windows PowerShell 5.1; Git доступен; node, npm, pnpm, mise, hk, pitchfork, gh и Docker не найдены в PATH; wsl.exe сообщает, что WSL не установлен. Не делать вывод о полной физической установке инструмента только по PATH.

Разработать варианты «нативная Windows» и «WSL», объяснить, что нужно устанавливать и какие проверки провести после установки. Указать переносимый способ общей команды локально и в Actions, обработки env, запуска и остановки dev-процессов. Рекомендовать минимум инструментов. Не устанавливать ничего и не менять конфигурацию компьютера.

## Answer

Официальные релизы mise 2026.10.25, hk 2.11.0 и pitchfork 2.33.0 содержат Windows-сборки. Документация и исходники допускают native Windows как основной путь; обязательной установки WSL не обнаружено.

Существенные ограничения: shell inline-задач mise и строковых команд hk на Windows — cmd, не PowerShell терминала; hk 2.11.0 имеет встроенный Pkl evaluator; автоматический lifecycle daemons при смене каталога не заявлен для PowerShell. Для daemons нужны experimental-настройка, закреплённый pitchfork и явные start/stop. Наличие поддержки по документации ещё не подтверждает работу всего проекта: предстоят проверки установки, hooks, readiness и отсутствия сиротских процессов.

Рекомендация исследования — начать с native Windows, переносимых задач и явного запуска dev-серверов. hk и optional daemons рассмотреть при согласовании команд. WSL оставить альтернативой при реальной POSIX-зависимости.
